# 严重度定级策略（severity rubric）

用于把「验证通过（disposition=reportable）」的 finding 统一映射到四档严重度。
本文件是策略输入，验证阶段按其定级；后续可扩展为 `classify-severity` 独立重分级阶段。

## 四档定义

### critical（严重）
可直接造成严重业务损失或大范围失陷，通常无需特殊前置条件：

- 未鉴权远程代码执行（RCE）、命令注入
- 可直接读取任意文件/数据库全量数据（如未过滤的 SQL 注入落在核心库）
- 认证绕过、越权读取任意用户敏感数据
- 可直接利用的硬编码生产凭据（云密钥、数据库主密钥、签名私钥）

### high（高）
需少量条件或影响范围次一级：

- 认证用户可触发的高危注入（SQLi 落在普通业务库、模板注入、SSRF 到内网）
- 存储型 XSS 作用于敏感页面
- 越权操作（IDOR 改/删他人数据）
- 敏感信息泄露（密钥、token、PII）但利用链不完整

### medium（中）
影响有限或利用条件较多：

- 反射型 XSS
- 低危路径穿越（仅读非敏感文件）
- 依赖已知中危 CVE（无公开可直达利用）
- 不安全的默认配置、缺失安全头、明文传输

### low（低）
加固/卫生问题，不构成直接可利用漏洞：

- 弱加密算法提示、缺失日志脱敏
- 信息性暴露（版本号、调试端点泄露非敏感信息）
- 可改进但暂无直接风险的问题

## 定级规则

1. 先判断 **是否确实 reportable**；定级只对 reportable finding 进行。
2. 按 **可达性 × 影响** 评估，而非按类别标签机械映射——同一类漏洞因上下文不同严重度可不同。
3. 证据不足时不得拔高严重度；宁可 `deferred`（待深查）也不臆断。
4. 硬编码生产凭据、RCE、认证绕过默认从 `high` 起评，存在可直达利用再升 `critical`。

## 输出约定

在 finding JSON 的 `severity` 字段写四档之一；在 `evidence` 里说明定级依据（可达性、前置条件、影响范围）。
